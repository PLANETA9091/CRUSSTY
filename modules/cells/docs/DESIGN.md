# c-cells — сервер как симулированный живой организм

> **Резюме.** `c-cells` — c-plugin модуль, превращающий сервер в **симуляцию
> живого организма**: мир — карта клеток, каждая клетка — нейрокомпартмент
> пирамидальной клетки коры человека (HL2/3 PC), воспроизведённый по репозиторию
> `human_cell` (Eyal et al., eLife 2016). Нейронная динамика (`na`/`kv`/NMDA,
> Cm ≈ 0.5 µF/cm²) — **не метафора, а вычисляемое ядро управления**. Она
> решает: (1) какие клетки мира тикать в этом тике и с каким темпом
> (спайковая регуляция), и (2) какие методы ядра переоптимизировать, когда
> клетка хронически перегружена («пластичность» на ClassFileLoadHook).
>
> Это не метафорическая обёртка и не статическая сетка регионов: параметры
> биологические и взяты из реального репозитория человеческого нейрона.

---

## 1. Биологическая база (human_cell)

Репозиторий `neuron_sim/human_cell/` сопутствует работе *Eyal G et al., 2016*
(eLife: «Unique membrane properties and enhanced signal processing in human
neocortical neurons»), автор — Guy Eyal (Hebrew University).

> **Важно: мы не копируем эту модель — мы её используем.**
> Репо для нас — научный источник: источник измеренных величин и описанных
> явлений, а не код для портирования. Мы не переносим `.mod`/`.hoc`/`.py`,
> не импортируем морфологии и не реплицируем NEURON. Мы берём из науки
> *числа и закономерности* (как цитируют статью), а проектируем свою
> архитектуру — под задачу живого сервера (тик 20 мс, load-границы,
> CPU-бюджет). Отсюда таблица ниже — это «цитируемые значения», не «требования
> к реализации».

| Известное значение/явление (цитируется) | Откуда | Как используется |
|---|---|---|
| Cm ≈ 0.5 µF/cm² (0.46–0.49 у конкретных клеток) | ст. Eyal 2016, `.hoc` фиты | константа мембраны наших клеток |
| Порог спайка, рефрактерность, адаптация | физиология HL2/3 | качественное правило «спайк→пауза» |
| Шипики: ×1.9 ёмкости/проводимости дальше 60 µм от сомы | `.hoc`, Benavides-Piccione 2013 | закон «близко к соме — гладко, дальше — чувствительнее» |
| NMDA: медленный возбуждающий вход | `mechansims/NMDA.mod` | медленная компонента возбуждения |
| Разрешение морфологии ~40 µм | `geom_nseg` | шаг дискретизации, порядок величины |
| Человеческий нейрон откликается быстрее (низкий Cm) | вывод статьи | спайковая регуляция влезает в 20 мс тик |

> **Честная модель.** Численные уравнения и структура организма — наши
> собственные (простая канальная динамика, дискретное время
> `dt ≈ 1 мс`, ≤ 20 шагов на серверный тик). Мы воспроизводим *качественную*
> биологическую динамику (порог, рефрактерность, утомление, гомеостаз),
> а не научные кривые статьи. Полная multi-compartment симуляция
> (300 синапсов × 1000 trial, `run_cm09.py`) в тиковых масштабах —
> исследовательская задача, не «рантайм».

### 2.1 Жизнь клетки

`NeuronState` (один компартмент, совместимый по каналам с HL2/3):

```
v      — мембранный потенциал, rest ≈ -70 мV
m, h   — Na+ гейтинг (minf(v), mtau(v) — формула efun, как в na.mod)
n      — K+ гейтинг
g_nmda — NMDA-кондукция (медленный вход)
Cm = 0.5 µF/cm²; gl, El — пассивная утечка
```

Шаг на `dt` (cnexp):

```
I = gl(El−v) + gna·m³h(Ena−v) + gk·n⁴(Ek−v) + I_nmda + I_syn
v += dt/Cm · I
m  = minf(v) + (m − minf(v))·exp(−dt/τ_m(v))        // и h, n
```

**Входные токи (`EPSP`)** — это события мира: число сущностей в клетке,
писания чанка, спаун/активность игроков, MSPT участка. Хроническая перегрузка
долбит мембрану до порога — клетка **спикает**, затем входит в рефрактерность
(не может спикать повторно N тиков — физическое «утомление»).

### 2.2 Спайки → тик-решения

- После каждого тика ядра (~20мс): `organism.step(dt)` — один шаг нейро-пакета.
- Клетки со спайком теперь = «tick candidates» следующего тика.
- **Тормозные синапсы** между соседями: перегруженная клетка спикает и
  урезает темп соседей (разгрузка) — саморегуляция организма.
- **Возбуждающие синапсы** в свободные регионы передают резерв тика —
  «лишние» клетки дополняются из суммарного пула (исключая полный тик всего мира).
- ТПС/время решения проверяется: если суммарное время тика решения уже
  съело весь тик — глобальное возвращение к консервативному «тикаем всё».

Передача в ядро происходит через существующий коннект:

- `scheduler::inject` / `scheduler::on_tick_boundary` (runtime)
- JVMTI hook на классы ядра через `cplug-sdk::hooks::register` / `cplug_sdk::retransform_class`
- элементы затронутого региона передаются через сигнатуры ядра (см. `dist` модуль).

### 2.3 Спайк → оптимизация методов

Хронически перегруженные клетки не только снижают свой тик-темп, но и
**«хотят» исполнять себя быстрее** — нейрональная пластичность запускает
`optimize`:

1. `profiler.rs` метит дешёво: краткосрочные сэмплы по счётчикам без полной
   инструментации (полная — 10–50% оверхеда).
2. Метод ассоциирован с рабочей клеткой; если он спикает ≥ `K` раз за окно —
   применяется перезапись:
   - специализация по стабильным типам/путям (снятие полиморфного
     dispatch, сокращение неуспешных inline),
   - удаление избыточных аллокаций на горячих call-путях,
   - упрощение проверок в горячих путях.
3. **Взаимодействие с JIT, не против него.** JIT уже доводит горячие пути до
   C2 хорошо. Мы целимся в методы, которых JIT не «доводит»: слишком большие
   для inline, полиморфные call-пути, прикованные к интерпретатору.
4. Семантика сохраняется: правила консервативны (не меняются сигнатура,
   синхронизация, модель исключений). Каждый патч логируется:
   `[cells] optimize net/NetHandler.go — removed 3 temporary allocs
   (neuron spike #42)`.

## 3. Честные границы

- **Оверхед.** Динамика одной клетки ≈ 50–200 флоп на тик; при 20k клеток
  <1% CPU (контроль telemetry). Если решения перестают помещаться —
  организм сам откидывает в консервативный режим.
- **Эффективность «человеческого нейрона»** качественная: Cm=0.5 — быстрые
  пороги, спайк-темп — адаптивная частота по регионам. Это не машинная
  нейро-симуляция в realtime и не обещание «мозга»; это биологичное и честное
  правило регулировки.
- Одна JVM, один процесс. Межсерверная «нервная система» — в модуле `dist`.
- `CRUSSTY_CELLS=0` / отсутствие клеток (мира 0) → no-op.
- Сервер остаётся MC-совместимым: изменения — только performance-свойства
  тика и «тепло» методов, без ломающих API изменений (для модулей).

## 4. Дизайн-источники (по workflow-правилу)

- SNN / event-driven адаптивное планирование: Rajammal & Chinnadurai, Sci Rep
  2025 («Dynamic load balancing … SNN»), **SpikingRM** (Springer; SNN+RL) —
  спайковое (event-driven) правило: нейроны считают только по «значимым»
  изменениям, экономия в real-time.
- Нейрон HL2/3 человека: Eyal et al. 2016 + репо `human_cell`
  (na/kv/NMDA, cnexp, морфы 6 PC).
- JVMTI-агенты для прода — **cplug-abi/cplug-sdk**: dispatch_bytes,
  register_hooks, weave — точечно, с учётом оверхеда инструментации
  (10–50% при полной — держимся точечно).
- Tiered JIT (C1→C2 профилирование→optim) — HotSpot — всё адаптивно;
  наш ход — дополнение, а не замена JIT.

## 5. Roadmap (этапы реализации)

1. `neuron` (порт каналов + тесты на спайк/рефрактерию) — чистый Rust, без JNI.
2. `organism` (карта, синапсы, события-входы) — интеграция с признаками
   загрузки из kernel (MSPT/entities).
3. `driver/scheduler` — спайковые биты тика + провал к консервативному.
4. `optimize` — profiler + точечные патчи через SDK weave/hooks.
5. E2E на Purpur + бенчмарк «cells vs обычный тик» (TPS/MSPT/telemetry).
